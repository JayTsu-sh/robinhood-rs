# Lustre 在线冷热分层采用同文件系统池迁移

robinhood-rs 通过 `liblustreapi` 在同一个 Lustre 文件系统内迁移文件数据的 OST 布局。降温和升温均保留原 FID、路径及硬链接，客户端继续通过原路径读取文件。分层状态由 Lustre 的实际布局决定，因此在迁移重试或 changelog 重放时，可以按同一 FID 重新核对数据的落点。

首版池迁移只处理尚未通过原生 HSM 归档且没有活动 HSM 操作的在线文件。已经归档、已释放或有活动 HSM 操作的文件继续由原生 HSM 策略管理。通过此约束明确两类策略在同一文件系统内的处理范围。

冷热池共享文件系统的元数据服务。池迁移期间，目标池需要足够空间容纳新布局的数据。交换成功后，关闭临时文件描述符会回收旧布局。实验结果见 [在线冷热分层方案](../LUSTRE-POOL-TIERING-PLAN.md)。
