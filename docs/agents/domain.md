# Domain docs

This repository uses one domain glossary at the root in `GLOSSARY.md`. Architecture decision records live in `docs/adr/`.

Before exploring a feature, read the glossary and the ADRs relevant to that feature when those files exist. Use the glossary's terms in specs, tickets, and tests. If a proposal revisits a recorded decision, cite the ADR and explain the trade-off.

Create the glossary when a domain term is settled. Add an ADR when a hard-to-reverse decision needs its rationale recorded. Use `domain-modeling` to record terms and decisions during `grill-with-docs`.
